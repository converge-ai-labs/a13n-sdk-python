# Observation and Data Access

## Finite Interaction and Advanced Thread SSE

The [finite Interaction](02-interaction-and-control.md#finite-observation) is the primary observation API: it binds the exact incorporating Run first, filters foreign Run and unscoped signals, and ends when that Run seals. The pinned [Thread stream contract](../contract/semantics/facts-and-delivery.md#the-thread-stream) owns the advanced persistent transport semantics. The generated `client.api.threads(thread_id).stream` child retains the original SSE HTTP operation. An advanced caller may explicitly construct `ThreadStream(client.api.threads(thread_id), run=None, position=None, after=None, reconnect=True, max_reconnects=5, max_event_bytes=1048576)` as a single-use, Thread-wide parser. Neither the generated resource nor the ordinary authored Thread injects a persistent high-level `events()` workflow. Enter with `async with`, then use `async for frame in stream`; exit or `aclose()` releases the HTTP attachment. Breaking iteration alone does not close the context. One stream supports one active reader. Client close or caller cancellation ends local I/O but not the remote Run.

`ThreadFrame` is a discriminated union of `DeltaFrame`, `BoundaryFrame`, `ChangedFrame`, `ResetFrame`, and `GapFrame`. Each has a literal `event_type` and read-only typed `data`. Testing `event_type` or the concrete class narrows both payload fields and cursor: `str` for delta/boundary, `None` for the other three. The parser validates these envelope fields (including ItemRef), but the nested AG-UI event is an open JSON object, not a claimed validated AG-UI event union. Read-only payload mappings are shallow; nested arbitrary JSON retains normal JSON values. Its five event names have distinct roles:

| Frame      | `cursor`       | Caller action                                                          |
| ---------- | -------------- | ---------------------------------------------------------------------- |
| `delta`    | Redis entry ID | Apply provisional event and item change                                |
| `boundary` | Redis entry ID | Committed display covers the named attempt sequence                    |
| `changed`  | `None`         | Re-read the Thread for inbox or pointer changes                        |
| `reset`    | `None`         | Discard affected Run output and re-read its items                      |
| `gap`      | `None`         | Read affected Run items; reassess coverage through optional `position` |

`DeltaData.item` is required and nullable. Its `ItemRef` requires `id`, `kind`, and `state`; optional nullable `ordinal` is a positive 1-based display coordinate, `response_group` identifies a response group, and `failure` preserves an arbitrary JSON mapping. Optional nullable `memory_sources` uses the public `a13n.streaming.MemorySource`, `RecordSource` and `FileSource` typed dictionaries. The parser validates the pinned nested provenance shape while preserving omitted defaults, explicit null, empty lists and false flags. The SDK validates known envelope fields without discarding additional ItemRef fields.

Nested events use native AG-UI 1.0 canonical camelCase fields. The SDK retains `subagentRunId`, native message/tool IDs, structured tool-result content parts, media sources, metadata, unknown custom payloads and required null values without flattening or legacy aliases. The Service envelope `run_id` identifies the managed Run; nested Harness Run and child identifiers are attribution, not Service continuation handles. Child content remains in that managed Run's observation; consumers namespace display identity by child attribution. A child lifecycle or nested `RUN_FINISHED` never seals the finite Interaction. Saved Items retain bounded structured content and attribution; neither Items nor delivery events are lossless execution history.

No Run-level SSE, terminal Service Run frame, notification WebSocket, or implicit projection cache is exposed. The finite Interaction uses exact Run readback to terminate, not a special SSE frame. A Thread SSE EOF never proves Run completion. An absent cursor on `changed`/`reset`/`gap` is intentional: these frames cannot be used as `Last-Event-ID`. A gap can be followed by connection EOF, so the application must perform explicit readback even if reconnection is enabled.

The read-only `stream.response` describes the latest successful HTTP handshake (status, headers, request ID); `is_closed` and `last_received_cursor` describe local lifecycle and last yielded cursor-bearing frame. Headers do not expose the response body. Framing and decoded payloads have a configured byte bound; malformed or truncated frames raise `ProtocolError`. Heartbeats are ignored.

## Session Snapshot Stream

`SessionStream(client.api.sessions(session_id), max_event_bytes=None)` opens one single-use, single-reader connection to the native Session stream. Session snapshots have no default client-side frame-size ceiling; an explicit positive byte limit bounds framing and closes oversized connections. HTTP error bodies retain the bounded transport read. The generated `.stream.get_stream()` remains raw response access. `SessionFrame` is the discriminated union of `SessionThreadFrame`, `SessionItemsFrame`, `SessionDeltaFrame`, and `SessionGapFrame`, each with a literal `event_type` and complete generated attrs payload (`ThreadState`, `RunSnapshot`, `Delta`, `Gap`). Session-only continuation definitions are generated from the pinned Session schema and share equivalent Native models. Known payloads are validated against that packaged schema before construction; arbitrary AG-UI event objects retain the schema's open JSON shape. Unknown event names are ignored before JSON decoding.

Each instance is a fresh-snapshot boundary. It sends no cursor or Last-Event-ID and performs no automatic reconnect. Clean EOF ends iteration; transport and HTTP errors remain distinct; invalid known frames terminate with ProtocolError. Successful response metadata and the local closed state are observable. Context exit, explicit local close, caller cancellation and Client shutdown release the HTTP attachment without mutating remote execution.

The receiver replaces Thread and pointed-Run views on `thread`, replaces Run Items from ordinal `first` on `items`, and holds a gapped Run's deltas until its next Items base. The continuation is protocol state, not an SDK-owned UI reducer. Before another connection, the application discards unfinished state from the prior connection. Runs sealed while disconnected require explicit historical Items reads. Thread cursors and Items ordinals cannot resume a Session stream.

Caller-owned reconnect follows the pinned native policy: reconnect after any end except invalid frames or 4xx other than 429; full jitter below `min(30s, 0.5s * 2**n)`, honor Retry-After on 429/503, reset consecutive failures only after 30s stable connection. Finite Interaction continues using its exact Run and Thread stream; Session observation introduces no implicit successor-follow workflow.

## Text Preview

`Interaction.text_stream()` lazily yields string chunks from the same finite reader. It emits root assistant CONTENT only after a trustworthy START and excludes explicit child attribution and display:false. At most 128 active message identities are tracked; content/transcript buffers are not accumulated. Interleaved messages preserve delivery order. Concurrent raw/text readers and multiple preview consumers are rejected. Breaking a paused preview requires explicit iterator closure or Interaction context exit for local cleanup.

Gap/reset, attempt or Service per-attempt sequence discontinuity, missing/ambiguous or duplicate START, non-string visible CONTENT, malformed protocol and active-state exhaustion interrupt preview with sticky `PreviewInterrupted(reason, run_id)`. Sequence tracking covers every exact-Run delta before semantic child/hidden filtering. The first observed coordinate anchors the local high-water mark; subsequent deltas must be dense. A boundary at or below the high-water mark is a notification and never moves it backwards; a boundary beyond it interrupts preview. Nested event/source coordinates and foreign Runs do not change this tracking. Preview stops without closing the exact outcome observer; result remains usable inside the open Interaction, and deliberate sequential raw consumption is permitted. No baseline repair or display fold is performed.

The pinned `a13n.stream.fragment` envelope contains slices of an original large CUSTOM event, not standard text-message suffixes. After excluding foreign, child and explicit hidden frames, an exact-root fragment conservatively interrupts because this projection does not assemble original custom semantics. Its opaque ID/data are not inspected for attribution or inner event names. This unsupported-framing limitation is not a claim that every fragment contains assistant text. Unknown unframed CUSTOM events are ignored by preview and preserved by raw iteration. Final Run output remains authoritative even when preview fails.

## Checkpoints and Recovery

1. The application may supply a paired `run` and canonical `position` (`{attempt}-{sequence}`) claiming its existing display coverage. These query values remain unchanged on this stream's reconnects; the SDK never derives or advances coverage from a Redis entry ID. `after` is a separate last *applied* Redis entry ID, sent as `Last-Event-ID`; Items reads supply no transport hint or coverage. With no query pair, existing cursor-only Service behavior remains unchanged.
2. The SDK yields a frame without persisting application progress. The application applies its projection and commits its own checkpoint.
3. When the consumer requests the next frame, the SDK acknowledges the previously yielded cursor-bearing frame **in memory** for reconnect. Yielding, prefetching, heartbeats, and ID-less frames do not advance that acknowledgement.
4. A gap preserves its optional canonical `position`, including explicit null and omission permitted by the current schema. The application explicitly reads that Run's Items to replace provisional display, while keeping the preview incomplete until it can establish coverage independently. Items readback supplies no stream position or continuation. Reset discards superseded attempt output. The SDK never silently reads back or merges a snapshot into event history.

The pinned Service contract, not a client precedence rule, determines replay. With a run/position pair, direct seeking uses the optional Redis hint only when its Run and attempt match the claim and active execution, and its sequence is covered. Absent, expired or incompatible hints fall back to retained replay filtered by the claimed position; their absence alone does not imply a gap. Covered boundaries remain visible, and an older-attempt claim receives reset. Fixed coverage across SDK reconnects can cause replay of already-applied output beyond that original coverage; an application must reconcile such delivery rather than assume exactly-once events.

Automatic reconnection is only for this read-only attachment. It retries transient transport/EOF and handshake `429`, `502`, `503`, `504` with bounded exponential jitter and `Retry-After` consideration. It does not replay mutations. The retry budget resets only when a *new cursor-bearing frame* is consumed by the next read; a successful handshake, heartbeat, `changed`, `reset`, `gap`, and EOF do not reset it. Thus repeated gap-only reconnects exhaust the budget rather than looping forever. With reconnection disabled, clean EOF ends iteration; a transport failure is an error. After retry exhaustion the last safe `TransportError` or `ApiError` is raised. Protocol errors and caller cancellation are not retried. Applications needing a total time bound use an outer timeout.

A delivered cursor is not a durable application checkpoint. Background-processing a frame while requesting another can advance the in-memory acknowledgement before that work finishes; applications serialize processing or reattach from their own applied cursor after failure. No exactly-once delivery claim is made.

## Readback and Pagination

- `run.get()` reports authoritative Run state, including `waiting` and `pending`. `run.items.get(before=UNSET, after=UNSET, limit=UNSET)` makes one native ordinal-window request, not a cursor collection traversal. Items have required dense 1-based `ordinal`; `before` >= 1 and `after` >= 0 are exclusive bounds and cannot be combined. The Service default limit is 200, maximum 500; server errors propagate without retry or client-side policy.
- A default read returns the newest limit plus the entire mutable tail, which can exceed the limit. Every Items response contains `run`, `items` and `complete`, with no `baseline`, `continuation`, `position` or `resume_after`. An Items read cannot install stream coverage.
- Explicit `before` or `after` reads return historical ordinal windows. `complete` means the Run is sealed, not that all history was loaded. Finite Interaction completion uses exact Run readback, never a historical window's flag. Applications explicitly request earlier pages.
- Saved `Item.content_refs` maps content field names to immutable `ContentRef` values. `client.api.runs(run_id).contents(content_id).get()` explicitly reads the authorized `RunContent` value with its media type, truncation flag and HTTP evidence. Neither finite observation nor text preview fetches or expands a content reference. Each reference belongs to its owning Run's committed display; Service distinguishes `not_found` from missing/damaged-object `unavailable`.
- Reply provenance arrives in `delta.item.memory_sources` and saved `Item.content.memory_sources`, with typed continuation state. It records automatic memory deliveries, not causal attribution or historical content reconstruction. Record Memory readback separately preserves optional nullable `provenance`, nullable creation source, confirmed last write and `content_matches`.
- `collection.list(...)` makes one request; `pages(...)` lazily yields `Result[Page]` with original filters, opaque next cursor, and HTTP evidence. `iter(...)` flattens ordinary page items. Empty pages with next cursors do not end traversal; non-advancing cursors fail explicitly. Pagination does not promise snapshot isolation.
- Retained screenshot references are read explicitly through `client.api.runs(run_id).images(image_id).get()` or `.get_stream()`. JPEG and PNG remain raw bytes with their actual Content-Type; reads neither capture a new screenshot nor expand image references during observation. Native authorization, retention and error responses remain visible.
- Binary downloads use generated `get_stream()` response contexts where exported; the caller checks status and consumes chunks before exit. Buffered generated `get()` remains available. Multipart uploads use a caller-owned binary source and leave it open; transport cancellation does not imply rollback of a staged upload or published Asset.

Finite observation, exact waiting, and local stream cleanup send no mutation. Explicit Run commands remain separate from the stream and retain their normal Service preconditions and unknown-outcome rules.
